# Bugfix Requirements Document

## Introduction

The `npm run build` command (webpack production build) compiles successfully but produces 435 warnings across 3 entry points (global.scss, utilities.scss, generated/_custom-properties.scss). These warnings fall into 5 categories: legacy Sass JS API deprecation, @import rule deprecation (~400+ warnings), deprecated global built-in functions, deprecated color functions, and asset size limit warnings. The bulk of warnings stem from Sass @import statements that should be migrated to @use/@forward, and from the sass-loader using the deprecated JS API. Foundation Sites warnings from node_modules cannot be fixed at source and must be silenced via configuration.

## Bug Analysis

### Current Behavior (Defect)

1.1 WHEN `npm run build` is executed THEN the build produces 435 warnings in the console output, obscuring any real errors or actionable information

1.2 WHEN sass-loader 13.2.0 compiles any SCSS entry point THEN it emits a "Legacy JS API" deprecation warning because it defaults to the deprecated Dart Sass JS API (1 warning per entry point, 3 total)

1.3 WHEN any SCSS file uses an `@import` statement THEN Sass emits a deprecation warning because `@import` is deprecated in favor of `@use`/`@forward` (~400+ warnings across all entry points and component builds)

1.4 WHEN `src/utilities/_grid.scss` uses the global `type-of()` function (lines 168, 185) THEN Sass emits a deprecation warning because `type-of()` should be `meta.type-of()`

1.5 WHEN `src/vendor/foundation/_settings.scss` uses the `darken()` color function (lines 819, 820, 825, 827) THEN Sass emits a deprecation warning because `darken()` should be replaced with `color.adjust()`

1.6 WHEN Foundation Sites internal SCSS files (node_modules) use deprecated global built-in functions (`map-values()`, `index()`, `type-of()`, `append()`) THEN Sass emits deprecation warnings that cannot be fixed by editing project source code

1.7 WHEN the build produces `utilities.css` at 512 KiB THEN webpack emits 3 asset size warnings because the file exceeds the recommended 244 KiB limit

### Expected Behavior (Correct)

2.1 WHEN `npm run build` is executed THEN the build SHALL produce zero warnings (or only unavoidable third-party warnings silenced via configuration), providing a clean build output

2.2 WHEN sass-loader compiles SCSS entry points THEN it SHALL use the modern Sass compiler API (via `api: 'modern-compiler'` option or sass-loader v14+), eliminating the legacy JS API deprecation warning

2.3 WHEN SCSS files reference other SCSS partials THEN they SHALL use `@use`/`@forward` instead of `@import`, eliminating all @import deprecation warnings from project source files

2.4 WHEN `src/utilities/_grid.scss` checks the type of a value THEN it SHALL use `meta.type-of()` (with `@use 'sass:meta'`) instead of the deprecated global `type-of()` function

2.5 WHEN `src/vendor/foundation/_settings.scss` darkens a color THEN it SHALL use `color.adjust($color, $lightness: -N%)` (with `@use 'sass:color'`) instead of the deprecated `darken()` function

2.6 WHEN Foundation Sites internal SCSS files emit deprecation warnings THEN the sass-loader configuration SHALL silence those specific deprecations (via `silenceDeprecations` option) since they originate from third-party code in node_modules

2.7 WHEN the build produces large CSS assets THEN webpack SHALL be configured with an appropriate `performance` setting (e.g., `performance: { hints: false }` or increased `maxAssetSize`) to suppress asset size warnings for this CSS library

### Unchanged Behavior (Regression Prevention)

3.1 WHEN `npm run build` is executed THEN the build SHALL CONTINUE TO compile successfully without errors and produce the same CSS output files (dist/css/global.css, dist/css/utilities.css, dist/css/tokens.css, and all component CSS files)

3.2 WHEN the generated CSS files are compared before and after the migration THEN the CSS output SHALL CONTINUE TO be functionally identical (same selectors, properties, and values)

3.3 WHEN Foundation Sites mixins are invoked via the sq-* adapter pattern in `src/vendor/foundation/_adapter.scss` THEN they SHALL CONTINUE TO produce the same CSS output

3.4 WHEN `src/base/_app.scss` and `src/utilities.scss` use nested `@import` statements inside selector rules (`.layout-container`, `.reveal`) THEN the migrated equivalent SHALL CONTINUE TO scope those styles within the same selectors

3.5 WHEN component SCSS partials are compiled individually (via webpack component entries) THEN they SHALL CONTINUE TO receive the shared configuration from `_index.scss` via sass-loader's `additionalData` and produce correct component CSS

3.6 WHEN design tokens generated by Style Dictionary are consumed by SCSS files THEN the token variables, spacing maps, and color maps SHALL CONTINUE TO be available and resolve to the same values

3.7 WHEN the `prebuild` step runs token validation and Style Dictionary generation THEN it SHALL CONTINUE TO work without changes
