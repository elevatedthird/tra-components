# @transamerica/sequoia-styles

Sequoia Design System — CSS library with design tokens, global styles, components, and utilities.

## Directory Structure

```
src/
├── _index.scss              # Main entry point (config, variables, mixins, settings)
├── global.scss              # Global stylesheet → dist/css/global.css
├── utilities.scss           # Utilities stylesheet → dist/css/utilities.css
├── base/                    # Global/base styles (typography, colors, buttons, grid, etc.)
├── components/              # UI components — each in its own sq-* directory
│   ├── _index.scss          # Barrel file — imports all component SCSS
│   ├── sq-accordion/        # SCSS, JS, Twig template, component YAML
│   ├── sq-card/
│   ├── sq-hero/
│   ├── sq-modal/
│   ├── sq-tabs/
│   └── ...                  # 30 components total
├── utilities/               # Utility classes (animation, colors, grid, typography, etc.)
├── mixins/                  # Custom Sequoia mixins
├── vendor/                  # Third-party framework adapters
│   └── foundation/          # Foundation Sites wrappers (sq-* namespaced)
├── generated/               # Auto-generated by Style Dictionary (gitignored)
│   ├── _variables.scss      # SCSS variables from tokens
│   └── _custom-properties.scss  # CSS custom properties (--sq-* prefix)
└── assets/                  # Fonts and images

tokens/                      # Design token source files (JSON)
├── color/                   # Brand, vibrant, contrasting, neutral, UI, link, form
├── typography/              # Font family, weight, size, line height
├── spacing/                 # Spacing scale
├── shadow/                  # Elevation / box shadows
└── breakpoint/              # Screen breakpoints
```

## Component Structure

Each component lives in its own `sq-*` prefixed directory under `src/components/` and can contain:

| File | Purpose |
|---|---|
| `_sq-{name}.scss` | Component styles (SCSS partial) |
| `{name}.es6.js` | Component JavaScript (ES6 source) |
| `sq-{name}.twig` | Twig template |
| `sq-{name}.component.yml` | Component metadata |
| `sq-{name}.css` | Compiled CSS (build output) |
| `{name}.js` | Compiled JS (build output) |

Sub-components get their own directory (e.g., `sq-accordion-item/` is separate from `sq-accordion/`).

Not every component has all file types — some are template-only (Twig + YAML), some have SCSS but no JS.

## Installation

```bash
npm install @transamerica/sequoia-styles
```

## Usage

### Importing Styles

```scss
// Main entry point — includes all config, variables, mixins, and settings
@import '@transamerica/sequoia-styles/src/_index.scss';

// Global styles (compiles to dist/css/global.css)
@import '@transamerica/sequoia-styles/src/global.scss';

// Utilities (compiles to dist/css/utilities.css)
@import '@transamerica/sequoia-styles/src/utilities.scss';

// All components
@import '@transamerica/sequoia-styles/src/components/_index.scss';

// Individual component SCSS
@import '@transamerica/sequoia-styles/src/components/sq-accordion/sq-accordion';
```

### Per-Component CSS and JS

Each component with SCSS or ES6 JS compiles its own standalone files during build.
You can consume them individually without pulling in the full global stylesheet:

```html
<!-- Component CSS only -->
<link rel="stylesheet" href="node_modules/@transamerica/sequoia-styles/src/components/sq-accordion/sq-accordion.css" />

<!-- Component JS only -->
<script src="node_modules/@transamerica/sequoia-styles/src/components/sq-accordion/accordion.js"></script>
```

### CSS Custom Properties

All design tokens are available as CSS custom properties with the `--sq-` prefix:

```css
.my-element {
  color: var(--sq-color-brand-warm-black);
  background-color: var(--sq-color-brand-pure-white);
  padding: var(--sq-spacing-4);
  font-family: var(--sq-typography-font-family-body);
  font-size: var(--sq-typography-heading-xl-font-size);
  box-shadow: var(--sq-shadow-elevation-1);
}
```

Include the standalone tokens CSS file for custom-property-only consumption:

```html
<link rel="stylesheet" href="node_modules/@transamerica/sequoia-styles/dist/css/tokens.css" />
```

### SCSS Variables

Token-generated SCSS variables preserve the legacy naming convention:

```scss
.my-element {
  color: $color--base--warm-black;
  padding: $spacing-4;
  font-size: $heading-xl-font-size;
}
```

## Build

```bash
# Full build (validates tokens, generates variables, compiles SCSS + JS)
npm run build

# Generate token outputs only
npm run tokens

# Validate token source files
npm run validate-tokens

# Run property tests
npm test
```

### Build Outputs

| Output | Description |
|---|---|
| `dist/css/global.css` | Compiled global styles |
| `dist/css/utilities.css` | Compiled utility classes |
| `dist/css/tokens.css` | Standalone CSS custom properties |
| `src/components/sq-*/sq-{name}.css` | Per-component compiled CSS |
| `src/components/sq-*/{name}.js` | Per-component compiled JS (from .es6.js) |

The build uses webpack with dynamic entry point discovery — any new `.es6.js` or `_sq-*.scss` file added to a component directory will automatically be picked up.

## Foundation Isolation

Foundation Sites dependencies are isolated behind Sequoia-namespaced wrapper mixins
in `src/vendor/foundation/_adapter.scss`. No files outside `src/vendor/` import Foundation directly.

```scss
// Use Sequoia wrappers
@include sq-xy-grid-classes;
@include sq-flex-classes;
@include sq-visibility-classes;
@include sq-breakpoint('medium') { ... }

// Don't call Foundation directly
// @include foundation-xy-grid-classes;
```

This allows future replacement of Foundation without changing consumer code.

## Token-Based Approach

Design tokens are the single source of truth. Values are defined in `tokens/*.json` and
transformed by Style Dictionary into SCSS variables, CSS custom properties, and JSON.

To update a design value, edit the token source file and rebuild:

```bash
# Example: update a brand color in tokens/color/brand.json, then:
npm run build
```

All generated outputs (SCSS variables, CSS custom properties, JSON) update automatically.
